# 2. 사용 시나리오

## 1. 로컬 기술 문서 업로드 및 등록 (R2, R2-1)

* 목적

  * 사용자가 가진 로컬 기술 문서를 특정 대화 세션의 지식베이스에 등록한다.

* 흐름

  * 사용자가 웹 UI에서 PDF, MD 또는 TXT 파일을 선택하고 현재 세션의 문서 등록을 요청한다.
  * 시스템은 파일 형식과 용량을 검증한 뒤 인덱싱 작업을 생성하고 작업 ID와 초기 처리 상태를 반환한다.
  * 사용자는 작업 ID로 상태 조회 API를 호출해 대기, 처리 중, 완료 또는 실패 상태와 진행 정보를 확인한다.
  * 시스템은 파일 텍스트를 파싱하고 청크로 분할한 뒤 Gemini Embedding API로 벡터화한다.
  * 각 벡터의 메타데이터에 세션 ID, 문서 제목, 파일명 등의 출처 정보를 저장한다.
  * 처리가 완료되면 생성된 청크 수와 완료 상태를 표시한다.

* 예외 흐름 (R2-1)

  * 지원하지 않는 파일 형식이나 용량 등 요청 검증 실패는 HTTP 400과 규격화된 JSON 오류 응답을 반환한다. 작업 생성 후 파싱 또는 임베딩에 실패하면 작업 상태를 실패로 갱신하고 상태 조회 결과에 오류 원인을 포함한다.

## 2. 외부 기술 문서 검색 및 지식베이스 확장 (R3, R3-1)

* 목적

  * 사용자가 찾는 기술의 공식 문서를 외부에서 검색해 현재 세션 지식베이스에 추가한다.

* 흐름

  * 사용자가 검색어(예: "Kubernetes HPA 설정")를 입력하고 현재 세션의 외부 문서 수집을 요청한다.
  * 시스템은 작업을 생성하고 작업 ID와 초기 처리 상태를 반환한다.
  * 시스템은 Gemini API에 "<찾는 정보 이름>에 관한 공식 기술 문서 찾아줘"라는 프롬프트를 전달해 공식 문서 후보와 URL을 찾는다.
  * 시스템은 후보 URL의 문서 내용을 가져와 텍스트를 추출하고 청킹 및 임베딩을 수행한다.
  * 생성된 벡터에 세션 ID와 원본 URL 등 출처 메타데이터를 저장한다.
  * 사용자는 작업 ID로 상태를 조회한다. 완료 시 수집한 문서 URL과 완료 상태를 표시한다.

* 예외 흐름 (R3-1)

  * 검색어 누락과 같은 요청 검증 실패는 HTTP 400과 규격화된 JSON 오류 응답을 반환한다. 작업 생성 후 검색 결과가 없거나 네트워크 및 문서 수집에 실패하면 작업 상태를 실패로 갱신하고 상태 조회 결과에 오류 원인을 포함한다.

## 3. 대화 세션 생성 및 지식 기반 질의응답 (R1, R4, R4-1, R4-2)

* 목적

  * 대화 세션별로 등록된 자료를 근거로 출처가 포함된 답변을 제공한다.

* 흐름

  * 사용자가 새 대화를 시작하면 세션을 생성하고 UUID 형식의 `session_id`를 발급받는다.
  * 사용자가 질문(예: "Kubernetes HPA 오토스케일링 조건 설정법 알려줘")을 전송한다.
  * 시스템은 질문을 벡터화하고 Vector DB에서 현재 `session_id`에 속한 청크만 검색한다.
  * 검색 결과의 유사도를 테스트를 통해 정한 임계값과 비교한다.
  * 기준을 충족하면 검색 문맥과 질문을 Gemini API에 전달해 답변을 생성한다.
  * 답변에는 사용된 자료의 출처를 표시한다. 업로드 자료는 제목과 파일명, 외부 자료는 URL을 표시한다.

* 예외 흐름 1 (R4-1)

  * 관련 문서가 없거나 검색 유사도가 임계값에 미달하면 Gemini API를 호출하지 않고 "등록된 문서 중 연관된 기술 정보를 찾을 수 없습니다."를 반환한다.

* 예외 흐름 2 (R4-2)

  * Gemini API 호출이 실패하면 오류 원인을 안내하고 규격화된 JSON 오류 응답을 HTTP 400으로 반환한다. 예: Rate Limit 초과 또는 API 인증 오류.

# 3. 완료 기준 체크리스트

* 세션 관리: `POST /api/v1/sessions` 호출 시 세션이 저장되고 유효한 UUID가 반환된다.
* 로컬 인덱싱: PDF, MD, TXT 등록 요청에 작업 ID가 반환되고 상태 조회로 처리 상태를 확인할 수 있다. 완료된 문서의 벡터는 해당 세션 ID와 함께 Vector DB에 저장되고 조회된다.
* 외부 인덱싱: Gemini 프롬프트로 공식 문서 후보를 찾고, 문서 URL을 통해 내용을 파싱해 인덱싱한다. 작업 ID, 상태, 원본 URL을 확인할 수 있다.
* RAG 질의응답: 검색은 현재 세션의 문서로 제한하며 답변에 업로드 자료는 제목과 파일명, 외부 자료는 URL을 출처로 표시한다.
* 유사도 임계값: 테스트 결과를 바탕으로 결정하며, 정해진 기준에 미달하면 LLM을 호출하지 않는다.
* 오류 처리: 오류 응답의 HTTP 상태 코드는 400으로 통일하고 규격화된 JSON 본문에 오류 코드와 원인을 포함한다.

# 4. 완료 기준 상세 설명

## 세션 관리 (R1)

* AC 1-1: 새 세션 생성 요청은 HTTP 201 Created와 고유한 `session_id`를 반환하고 세션 정보를 저장한다.
* AC 1-2: 세션 생성에 실패하면 HTTP 400과 명확한 오류 원인을 포함한 규격화 JSON 응답을 반환한다.

## 문서 인덱싱 및 외부 수집 (R2, R3)

* AC 2-1 (R2): PDF, MD, TXT 등록 요청은 인덱싱 작업을 생성하고 작업 ID와 초기 상태를 반환한다. 처리는 텍스트 파싱 -> 청킹 -> 임베딩 -> Vector DB 저장 순서로 진행된다.
* AC 2-2 (R2-1): 지원하지 않는 파일, 암호화되어 있거나 텍스트를 추출할 수 없는 PDF는 인덱싱을 중단한다. 작업 생성 전 검증 실패는 HTTP 400 및 오류 코드 `INVALID_FILE_FORMAT`을 반환하고, 작업 생성 후 실패는 상태를 실패로 갱신해 오류 코드를 상태 조회 결과에 포함한다.
* AC 2-3 (R2): 작업 상태 조회는 작업 ID를 받아 대기, 처리 중, 완료 또는 실패 상태와 가능한 처리 정보를 반환한다.
* AC 3-1 (R3): 외부 검색은 Gemini에 "<찾는 정보 이름>에 관한 공식 기술 문서 찾아줘" 프롬프트를 전달해 문서 후보를 찾는다. 상위 N개 후보의 본문을 파싱하고 임베딩해 Vector DB에 등록하며 원본 URL을 메타데이터에 기록한다.
* AC 3-2 (R3): 외부 수집 요청도 작업 ID를 먼저 반환한다. 작업 상태 조회 결과에는 처리 상태와 완료된 경우 수집한 URL이 포함된다.

## 세션별 검색, 답변 및 오류 처리 (R4)

* AC 4-1 (R4): 모든 인덱싱 벡터는 `session_id`를 메타데이터로 가진다. 질의 시 해당 세션 ID로 검색 결과를 필터링한다.
* AC 4-2 (R4): 답변에는 Gemini가 생성한 본문과 답변 작성에 사용된 출처가 포함된다. 업로드 자료는 제목과 파일명, 외부 자료는 URL을 표시하며 페이지 번호는 요구하지 않는다.
* AC 4-3 (R4-1): 검색 유사도 임계값은 테스트 후 결정한다. 결과가 임계값에 미달하면 Gemini API 호출을 생략하고 관련 문서 없음 안내를 반환한다.
* AC 4-4 (R4-2): Gemini API 오류 등 서비스 오류는 시스템 전체 중단 없이 처리하고 규격화된 JSON으로 원인을 안내한다. 동기 API 오류와 요청 검증 오류의 HTTP 상태 코드는 400으로 통일한다. 비동기 작업 생성 후 발생한 오류는 작업 상태를 실패로 갱신하고 상태 조회 결과로 제공한다.
