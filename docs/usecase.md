# 2. 사용 시나리오

## 1. 로컬 기술 문서 업로드 및 등록 (R2, R2-1)

  * 목적
  
    * 사용자가 가지고 있는 로컬 기술 문서를 시스템에 등록하여 RAG 지식베이스 구축

  * 흐름

    * 사용자가 웹 UI에서 architecture_guide.pdf 파일을 선택하여 등록 요청을 보낸다.

    * 시스템은 파일 확장자 및 용량을 검증한 뒤, 텍스트를 파싱하고 적절한 크기(Chunk)로 분할한다.

    * 분할된 텍스트 청크를 Gemini Embedding API를 이용해 벡터화한 후 Vector DB에 저장한다.

    * 인덱싱이 성공하면 "문서 등록 완료 (총 42개 청크 생성)" 메시지와 함께 인덱싱 완료 상태를 표시한다.

  * 예외 흐름 (R2-1)
  
    * 만약 이미지 기반 PDF이거나 확장자가 미지원(.docx 등)일 경우, 400 Bad Request와 함께 *"텍스트 추출에 실패했거나 지원하지 않는 파일 형식입니다."*라는 원인 메시지를 출력한다.

## 2. 외부 기술 문서 자동 검색 및 지식베이스 확장 (R3, R3-1)

  * 목적
  
    * 로컬에 문서가 없을 때 외부 인터넷 검색을 통해 기술 문서를 가져와 지식베이스에 추가

  * 흐름

    * 사용자가 검색창에 키워드(예: "Kubernetes HPA 설정 가이드")를 입력하고 외부 문서 수집 요청을 보낸다.

    * 시스템은 외부 검색 API(또는 크롤러)를 통해 관련 기술 웹문서/블로그/공식 문서를 검색한다.

    * 검색된 주요 문서 텍스트를 긁어와 시나리오 A와 동일하게 청킹 및 벡터화를 거쳐 Vector DB에 저장한다.

    * 수집 완료 후 검색된 문서 제목 및 URL 목록과 함께 "지식베이스 반영 완료" 상태를 반환한다.

  * 예외 흐름 (R3-1)
  
    * 인터넷 연결이 끊기거나 검색 결과가 존재하지 않을 경우, *"외부 문서 검색 실패: 검색 결과가 없거나 네트워크 연결에 실패했습니다."*를 반환한다.

## 3. 대화 세션 생성 및 외부/내부 지식 기반 질의응답 (R1, R4, R4-1, R4-2)

  * 목적
  
    * 대화 세션을 만들고 인덱싱된 지식을 바탕으로 질문에 대한 정확한 출처 기반 답변 획득

  * 흐름

    * 사용자가 "새 대화 시작" 버튼을 눌러 세션을 생성하고 Session ID (UUID)를 발급받는다. (R1)

    * 사용자가 *"Kubernetes HPA 오토스케일링 조건 설정법 알려줘"*라는 질문을 전송한다. (R4)

    * 시스템은 질문을 벡터화하여 Vector DB에서 코사인 유사도가 높은 상위 문서 청크들을 가져온다.

    * 검색된 문맥(Context)과 질문을 Gemini API에 전달하여 출처(문서명/URL)가 명시된 답변을 생성하고 사용자에게 출력한다.

  * 예외 흐름 1 (R4-1)
  
    * DB에 관련 문서가 전혀 없거나 유사도가 기준치(예: 0.7 이하)에 미달하면, LLM을 호출하지 않고 *"등록된 문서 중 연관된 기술 정보를 찾을 수 없습니다."*라는 안내를 반환한다.

  * 예외 흐름 2 (R4-2)
  
    * Gemini API 호출 중 Rate Limit 초과(429) 또는 API Key 만료 에러 발생 시, "AI 서비스 일시적 이용 불가 (API Limit 초과). 잠시 후 다시 시도해 주세요." 메시지를 출력한다.

# 3. 완료 기준 체크리스트

  * 세션 관리: POST /api/v1/sessions 호출 시 유효한 UUID 반환 및 저장

  * 로컬 인덱싱: PDF/MD/TXT 파일 전송 시 Vector DB에 100% 정상 저장 및 조회

  * 외부 인덱싱: 외부 URL/키워드 검색 결과 텍스트 파싱 및 인덱싱 성공

  * RAG 질의응답: 답변 하단에 [참조 출처: 파일명/URL, 페이지] 명시 필수

  * 예외 처리: 모든 에러 상황(400, 404, 500, 429)에서 규격화된 JSON 에러 응답 반환

# 4. 완료 기준 상세 설명

  * 세션 관리 (R1)

    * AC 1-1: 새로운 대화 생성 요청 시 HTTP 201 Created 응답과 함께 고유한 session_id가 발급되어야 한다.

    * AC 1-2: DB 연결 실패 등 세션 생성 불가 시 관련된 HTTP 응답과 함께 명확한 에러 원인 메시지가 반환되어야 한다.

  * 문서 인덱싱 및 수집 (R2, R3)

    * AC 2-1 (R2): .pdf, .md, .txt 확장자 파일 선택 시 텍스트 파싱 -> Chunking -> Embedding -> Vector DB 저장이 비동기 또는 동기 파이프라인으로 단방향 처리되어야 한다.

    * AC 2-2 (R2-1): 텍스트를 추출할 수 없는 암호화된 PDF 또는 이미지만 있는 PDF 업로드 시 INVALID_FILE_FORMAT 에러 코드와 함께 인덱싱이 중단되어야 한다.

    * AC 3-1 (R3): 외부 검색 요청 시 검색 결과 상위 N개 문서를 파싱하여 Vector DB에 정상 등록하고, 메타데이터에 원본 URL이 기록되어야 한다.

  * RAG 질의응답 및 예외 처리 (R4)

    * AC 4-1 (R4): 질의응답 결과에는 Gemini API가 생성한 답변 본문과 함께 답변 작성에 사용된 참조 출처(문서 제목, 파일명 또는 외부 URL)가 항상 명시되어 포함되어야 한다.

    * AC 4-2 (R4-1): Vector DB 검색 결과의 코사인 유사도가 임계값(예: 0.65) 미만일 경우, Gemini API 호출을 스킵하여 비용을 절감하고 관련 문서 없음 예외 메시지를 반환해야 한다.

    * AC 4-3 (R4-2): Gemini API 호출 중 429 Too Many Requests 또는 401 Unauthorized 발생 시 Graceful Degradation 처리를 통해 사용자에게 API 오류 사유를 친절하게 안내하고 시스템 다운을 방지해야 한다.
